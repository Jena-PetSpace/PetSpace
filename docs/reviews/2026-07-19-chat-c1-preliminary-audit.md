## 대상 선정

MY, Feed F1/F2, Health H1A~H1C, P2C는 Codex·Claude 공동 리뷰를
통과했다. 홈·AI 분석과 하단 5탭은 보호 상태이므로 다음 독립 UI/UX
후보는 채팅이 적합하다.

채팅은 프로필의 `메시지` 행동과 홈 상단 진입점에서 연결되고, 목록·새
채팅·대화·방 설정의 네 화면이 하나의 완결된 사용자 흐름을 이룬다.
UGC 신고·차단 계약도 이미 존재하므로 새 제품 의미를 만들기보다 현재
정확성과 신뢰도를 마감할 수 있다.

## 보존할 계약

1. `auth.uid()` 기준 차단·참여자·메시지 RLS와 K1 보호 계약
2. 차단 직후 기존·신규 메시지 비노출
3. 사용자·메시지 신고는 실제 `reports` 저장 성공 뒤에만 성공 안내
4. 1:1 기존 방 재사용과 그룹방 생성 RPC
5. 메시지 30개 cursor 조회와 중복 ID 방지
6. 이미지 미리보기와 다중 이미지 묶음 의미
7. 홈·AI 분석·하단 5탭 직접 변경 금지
8. 빨강 신규 추가 금지, 브랜드 action 색과 기존 의미 토큰 사용

## 권고 화면 구조

### 1. 채팅 목록

- 상단 검색, 새 채팅 행동
- 로딩·빈 상태·오류·불러온 목록을 분리
- 방 이름, 마지막 메시지, 시간, 안 읽은 수
- 명시적 더보기에서 설정·나가기
- 새로고침 실패 시 기존 목록 유지

### 2. 새 채팅

- 300ms 검색과 팔로잉 기본 목록
- 검색 실패·결과 없음 분리
- 선택 사용자를 상단 요약
- 1명은 `대화 시작`, 2명 이상은 그룹 이름과 `그룹 만들기`
- 생성 중 중복 제출 차단

### 3. 대화

- 1:1/그룹에 맞는 안전 메뉴
- 날짜 구분, 발신자 묶음, 이미지 메시지
- 최초·이전 메시지 추가 실패 분리
- 전송 실패 시 입력과 대상 파일 보존
- 메시지 신고는 명시적 사용자 행동과 실제 결과 연결

### 4. 채팅방 정보

- 참여자와 현재 사용자 역할을 먼저 표시
- 관리자만 이름·사진·초대 수정
- 실제 제공되지 않는 방별 알림은 과장하지 않음
- 나가기는 별도 위험 행동 영역

## 결론

채팅 C1을 홈·AI 분석 밖의 다음 UI/UX 대상으로 권고한다. 먼저
Codex 목업·작업지시서를 Claude Opus 4.8이 동일 47파일 읽기 전용 manifest로
검토했고 blocker/high 0으로 승인했다.

Claude가 추가로 확인한 보완은 다음과 같다.

1. 1:1·그룹별 신고·차단을 나누기 전에 방 `type`과 현재 참여자의 `role`을
   실제 데이터에서 확보한다.
2. 방별 알림 스위치뿐 아니라 목록 타일의 가짜 음소거 아이콘도 제거하되
   저장된 `SharedPreferences` 값은 삭제하지 않는다.
3. 실시간 새 메시지는 참여자 캐시로 발신자 이름·사진을 보강한다.
4. 새 메시지마다 실행되는 읽음 갱신과 참여자 재조회를 합친다.

Codex는 이 네 항목을 수용했다. C1A의 정확한 22파일 구현 범위를 사용자가
승인한 뒤 정확성·안전 구현과 테스트를 먼저 완료하고, 독립 교차 리뷰를
통과한 다음 C1B 네 화면 UI로 넘어간다.
