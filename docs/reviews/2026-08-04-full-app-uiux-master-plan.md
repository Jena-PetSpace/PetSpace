## 1. 한 번에 고정하는 제품 방향

PetSpace는 `AI 분석 결과를 보여주는 앱`만도, `반려동물 SNS`만도 아니다.
사용자가 매일 반려동물의 상태를 관찰하고 기록하며 필요할 때 이웃과 나누는
`차분한 케어 기록 서비스`로 정의한다.

전 화면은 다음 우선순위를 따른다.

1. 신뢰와 안전: 인증, 개인정보, 의료 오인 방지, 서버 정본, 복구 가능성
2. 핵심 행동: 기록, 분석 시작, 게시, 댓글, 메시지, 반려동물 관리
3. 관계와 탐색: 피드, 커뮤니티, 팔로우, 알림, 채팅
4. 참여 콘텐츠: MBTI, 퀴즈, 운세, 뉴스, 리워드
5. 장식: 핵심 행동과 상태 이해를 방해하지 않는 범위에서만 허용

권고 디자인 톤은 `차분한 케어 에디토리얼`이다. 진한 navy는 헤더·선택·주요
행동에만 쓰고, 본문은 흰색 또는 cool gray 표면과 얇은 경계로 구성한다.
그라데이션, 과한 그림자, 카드 중첩, 장식 이모지는 제거한다.

## 2. 고정 보호 조건

- Home 화면과 AI 분석 결과 화면은 이번 기획에 포함하지만 구현은 잠근다.
- 해당 두 범위는 사용자의 별도 해제 승인 전 수정하지 않는다.
- 로그인 화면의 원형 Apple → Google → Kakao 버튼은 보존한다.
- 하단 탭은 `홈 / 건강 / AI 분석 / 피드 / MY` 5개를 유지한다.
- AI 분석 탭은 기존 강아지 발바닥 아이콘을 일반 탭 크기와 위계로 사용한다.
- 피드 내부 명칭은 `피드 / 커뮤니티`로 유지하고 스토리 기능은 추가하지 않는다.
- 안전하지 않은 `팔로워만` 공개 범위는 서버 강제가 완성되기 전까지 노출하지 않는다.
- 레거시 `팔로워만` 또는 알 수 없는 visibility 값은 public으로 폴백하지 않는다.
  읽기 시 fail-closed로 숨기고 소유자에게만 공개 범위 재설정 안내를 표시한다.
- K1/H2, `auth.uid()` 기반 RPC, 차단·신고·건강 소유권 계약을 보존한다.
- Apple OAuth, URL scheme, entitlement, iPad `shareOrigin`을 변경하지 않는다.
- 운영 DB, Edge, APNs, signing, TestFlight, 스토어 배포는 이 기획의 실행 권한이 아니다.

## 4. 3회 독립 검토 결과

### 4.1 정보 구조·사용자 여정

- 루트 5탭은 유지하되 글쓰기·편집·상세·검사처럼 집중이 필요한 화면은
  루트와 시각적으로 분리한다.
- 한 화면의 primary action은 하나만 둔다. 저장, 다음, 게시, 재시도 가운데
  현재 단계에 필요한 하나만 채움 버튼으로 표시한다.
- `빈 상태`, `검색 0건`, `반려동물 0마리`, `차단으로 숨김`, `권한 거부`,
  `오프라인`, `부분 실패`, `서버 실패`, `세션 만료`를 서로 다른 상태로 표시한다.
- 가입 후 긴 튜토리얼은 첫 가치 도달을 늦춘다. 이메일 인증 → 약관 → 프로필 →
  반려동물 등록/나중에 이후 앱을 시작하고, 기능 안내는 첫 사용 맥락에 제공한다.
- 설정은 자주 바꾸지 않는 선택만 남기고 시스템 권한은 시스템 설정과 역할을
  명확히 나눈다.
- 참여 기능은 홈의 핵심 케어 행동보다 앞에 나오지 않으며 독립 task/detail
  화면에서 완료와 복기 경로를 제공한다.

### 4.2 시각·인터랙션·접근성

- 8/12/16/24 간격, 12/16 모서리, 1px 경계, 44pt 이상 터치를 공통 토큰으로 쓴다.
- 큰 색상 아이콘 박스와 카드 안의 또 다른 카드를 줄인다.
- 장식 이모지와 유니코드 동물 그림은 앱 화면, 빈 상태, 진행 문구, 결과 제목에서
  제거하고 정본 아이콘 또는 텍스트로 교체한다.
- 성공·실패·정답·선택 상태는 색상과 함께 아이콘, 제목, 경계, 설명 중 두 가지
  이상의 단서를 제공한다.
- iPad는 iPhone 열을 늘리지 않고 최대 읽기 너비 또는 list-detail/supporting pane을
  사용한다.
- Dynamic Type 200%, VoiceOver 읽기 순서, 키보드, SafeArea, 다크 모드를 모든
  배치의 완료 조건으로 둔다.

### 4.3 기능·백엔드·신뢰

- 낙관적 UI는 서버 실패 시 원래 상태로 롤백하고 사용자가 수행한 입력은 보존한다.
- 좋아요·저장·팔로우는 단일 캐시 엔티티를 정본으로 갱신하고 카드·상세·프로필에
  같은 상태와 카운터를 전파한다. 실패 시 상태와 카운터를 함께 롤백한다.
- pagination 실패는 전체 화면 실패로 바꾸지 않고 해당 목록 끝에서 같은 cursor로
  재시도한다.
- 오프라인 쓰기의 기본값은 `즉시 실패 + 입력 보존`이다. 채팅 client id 큐와
  게시글 임시저장처럼 별도 멱등·복구 계약이 있는 기능만 예외로 허용한다.
- 401/JWT 만료는 조용한 토큰 갱신을 한 번 시도한다. 실패하면 진행 중 task를
  로컬 draft에 저장하고 로그인 후 복원 여부를 한 번 묻는다.
- presentation에서 `Supabase.instance`로 현재 사용자를 직접 읽는 지점은 의존성
  주입 후보로 관리한다. UI 개선과 서버 계약 변경을 한 diff에 섞지 않는다.
- `failure.message`, `state.message`, 예외 `$e`를 UI나 release 로그에 직접 표시하는
  경로는 공개 안전 메시지로 치환한다.
- FCM과 realtime의 알림 본문·payload·record 로그는 출시 P0로 제거한다.
- Android release debug-signing fallback은 출시 P0로 차단한다.
- 의료·건강 분석은 진단으로 표현하지 않고 결과, 관찰 포인트, 수의사 상담 기준,
  참고 고지의 순서로 표시한다.

## 5. 탭·기능·페이지별 기획

### 5.1 인증·온보딩·설정·알림

권고안: 2026-08-03 W1 목업의 `A / A / A`.

- 로그인: 단일 배경, 이메일/비밀번호, 인라인 검증, 비밀번호 보기, 원형 소셜 로그인
- iPad 로그인: 최대 480pt와 수직 균형, 키보드 등장 시 스크롤
- 가입: 이메일 인증 → 약관 → 프로필 → 반려동물 등록/나중에
- 온보딩 정본 상태는 `미인증 / 약관대기 / 프로필대기 / 완료 / 탈퇴유예` 5개다.
  서버 상태가 정본이며 앱 재시작·재로그인 시 해당 단계로 복귀한다.
- 약관: 필수/선택 분리, 저장 실패 시 선택 보존
- 비밀번호 재설정: 계정 존재 비공개, `shouldCreateUser: false`, 6자리 OTP
- 설정: 컴팩트 inset grouped list, 위험 액션 별도 섹션
- 알림: 시스템 권한 상태 행 + 앱 master switch + 유형별 switch
- 회원탈퇴: 30일 복구 문구, Apple revoke, `탈퇴` 확인 입력 보존
- 로그아웃 상태에서 딥링크를 열면 대상 경로를 민감 파라미터 없이 일시 보관하고,
  로그인·온보딩 완료 후 한 번만 복원한다. 대상 삭제·차단이면 안전한 루트로 이동한다.

온보딩 redirect 정본:

| 서버 상태 | 허용 착지 | 다른 보호 경로 접근 시 |
|---|---|---|
| 미인증 | 로그인·이메일 인증 | 이메일 인증으로 이동 |
| 약관대기 | 약관·약관 상세 | 약관으로 이동 |
| 프로필대기 | 프로필 설정·반려동물 등록 | 프로필 설정으로 이동 |
| 완료 | 루트 5탭과 인증 사용자 경로 | 요청 경로 유지 |
| 탈퇴유예 | 계정 복구 안내 | 복구 또는 로그아웃 선택 전 루트 차단 |

### 5.2 MY·프로필·반려동물

- 사용자가 조정한 MY 상단 navy 배경, 프로필/대표 반려동물/통계 구성은 되돌리지 않는다.
- 프로필 이미지와 이름·통계 baseline, 카드 간 간격, 대표 반려동물 영역 높이만 정밀 조정한다.
- 내 게시글과 저장은 빈 상태에서 장식 그림 없이 제목·설명·CTA를 제공한다.
- 저장 컬렉션은 전체/미분류/컬렉션 수와 pagination 실패를 영역별로 표시한다.
- 프로필 편집은 사진·닉네임·소개의 변경 여부, 저장 중 잠금, 실패 시 입력 보존을 제공한다.
- 반려동물 관리 0/1/다견, 대표 선택, 편집, 삭제 보호를 분리한다.
- 반려동물 삭제는 soft delete + 30일 유예를 정본으로 한다. 삭제 전 건강 기록,
  AI 기록, 게시글 연결, 대표 반려동물 영향을 요약하고 취소·복구 경로를 제공한다.
- 유예 중에는 반려동물 본체와 전용 건강·AI 기록을 전 화면에서 숨기고 복구 시
  원상 복원한다. 사용자 소유 게시글은 유지하되 삭제된 반려동물 칩·연결만 숨기고,
  삭제 전 연결 게시글을 함께 정리할 선택지를 제공한다. 회원탈퇴 유예와 겹치면
  계정 복구가 먼저이며 계정 복구 전에는 반려동물만 별도로 복구할 수 없다.
- 대표 반려동물 삭제 전 남은 반려동물 중 새 대표를 사용자가 직접 선택하게 한다.
  마지막 반려동물이면 대표 없음 상태로 전환하며 자동 승계하지 않는다.
- pet editor는 필수/선택 필드와 사진 실패 복구를 같은 위치에서 제공한다.
- 공식 증명서로 오해할 수 있는 여권 표현에는 비공식 서비스 기록 고지를 유지한다.

### 5.3 피드·커뮤니티·소셜

- 루트 헤더 `PetSpace`, 내부 탭 `피드 / 커뮤니티`, 검색·글쓰기 순서를 유지한다.
- 피드는 사진 중심, 커뮤니티는 제목·본문·카테고리 중심으로 카드 문법을 분리한다.
- 사진 글과 커뮤니티 글 작성은 같은 task shell을 사용하되 필드와 저장 형식은 섞지 않는다.
- 최대 10장, 업로드 진행, 부분 실패, 재시도, 임시저장, 나가기 확인을 제공한다.
- 상세는 본문 → 상호작용 → 댓글 순으로 두고 신고·차단은 더보기 메뉴로 통합한다.
- 좋아요·저장·팔로우의 낙관적 상태는 중복 탭을 직렬화하고 실패 시 롤백한다.
- 검색은 사용자/게시글/태그/장소를 분리하고 각 0건·실패·더 불러오기 상태를 갖는다.
- 위치정보 정책이 별도 승인될 때까지 위치를 수집하지 않고 `장소` 검색·선택·목록을
  UI에서 숨긴다. 기존 위치 데이터는 출력 정밀도와 삭제 계약을 확인하기 전 재사용하지 않는다.
- 신규 위치 쓰기는 클라이언트와 서버 계약 양쪽에서 거부하고, 기존 위치 값과 검색
  인덱스는 조회 결과에서 제외한다. B3에서 기존 값의 삭제·내보내기 정책을 별도 확정한다.
- 레거시 `팔로워만`/미지 visibility 글은 비소유자에게 숨기고, 소유자에게만
  `공개 범위를 다시 설정해 주세요` 안내와 안전한 재설정 동선을 제공한다.
- fail-closed는 UI 필터가 아니라 `auth.uid()` 기반 서버 view/RPC/RLS에서 강제한다.
- 알림은 읽음 처리, 모두 읽음, 딥링크 대상 없음, 차단 대상 숨김을 구분한다.
- 신고 완료 후 과도한 성공 모달 대신 짧은 확인과 다음 안전 행동을 제공한다.

### 5.4 채팅

- 목록은 1:1/그룹, 읽지 않음, 마지막 메시지, 시간, pagination을 우선한다.
- 새 채팅은 검색 → 대상 선택 → 1:1 시작 또는 그룹 이름 확인 순서로 단순화한다.
- 상세는 키보드와 입력창 SafeArea, 텍스트/사진 1~10장, 전송 중·실패·재전송을 제공한다.
- 네트워크 복구 시 동일 local message가 중복 전송되지 않도록 client id를 유지한다.
- 앱 복귀·realtime 재연결은 `last_seen_message_id 이후 REST backfill → 중복 제거 →
  realtime 재구독` 순서로 실행한다.
- 차단 사용자는 목록·검색·초대·메시지 수신에서 같은 계약으로 제외한다.
- 1:1 방 설정에는 신고와 차단을 모두 제공한다. 차단 후 방은 읽기 전용 기록으로
  유지하되 목록에서는 숨기며, 해제 시 다시 보이게 한다.
- 방 설정은 실제 저장 계약이 있는 이름/멤버/나가기/신고/차단만 노출한다.
- 관리자만 가능한 행동은 권한 없는 사용자에게 비활성으로 남기지 않고 숨긴다.

### 5.5 건강

- 대표 반려동물 → 다음 케어 → 기록 필터 → 최근 기록 → 추이 순서를 유지한다.
- 반려동물이 0마리면 다른 건강 모듈을 숨기고 설명과 `반려동물 등록` CTA 하나만 표시한다.
- 기록 없음과 조회 실패를 분리하고, 등록 CTA는 기록 없음에만 제공한다.
- 건강 기록 5종은 full task editor에서 날짜·단위·필수/선택·메모를 일관되게 입력한다.
- 예방접종 신규 입력의 백신 종류 필수 검증과 기존 빈 값 호환을 유지한다.
- 편집·삭제는 원본을 유지한 채 실패 복구하고 삭제 영향 범위를 확인한다.
- 알림은 시스템 권한, 앱 선택, 기기 테스트, 실제 자동 예정 알림 준비 상태를 구분한다.
- PDF는 생성·미리보기·저장·공유 실패를 분리하고 긴 이름과 큰 글자를 지원한다.
- 의료적 이상 신호는 공포를 유발하는 빨간 화면보다 긴급도와 다음 행동을 명확히 한다.
- 긴급도 문구는 서비스의 보수적 관찰 가이드이며 진료를 대체하지 않는다고 고정한다.
  의학적 임계값을 제품팀이 임의 생성하지 않고, 근거·검수 주체가 없는 기준은 노출하지 않는다.

### 5.6 AI 감정·건강 분석 — 기획만, 구현 잠금

- 입력: 대표 반려동물, 사진 품질, 최대 장수, 촬영/갤러리, 권한 복구를 먼저 보여준다.
- 분석 중: 단계형 장식 문구보다 실제 업로드/분석 상태, 취소 가능 여부, 재시도를 표시한다.
- 비반려동물·흐림·신체 부위 부족 등 입력 품질 오류를 서버 오류와 분리한다.
- 결과: 핵심 요약 → 관찰 근거 → 보호자가 확인할 내용 → 다음 행동 → 참고 고지 순서로 정리한다.
- 감정 확률은 과도한 정밀도로 신뢰를 가장하지 않고 해석 가능한 범위로 표현한다.
- 건강 결과는 진단이 아니며 응급/빠른 상담/관찰의 행동 기준을 분명히 한다.
- 반려동물이 0마리면 분석 종류와 사진 선택을 숨기고 `반려동물 등록` CTA 하나만 표시한다.
- 기록·타임라인·추세·주간 보고서는 날짜와 데이터 출처, 저장 상태, 삭제/공유를 제공한다.
- 예외 `$e`, 내부 failure message, 민감 이미지 경로는 UI·로그·공유에 노출하지 않는다.

### 5.7 참여 기능: MBTI·퀴즈·운세·뉴스·리워드

- MBTI: 20문항 진행률, 이전/다음, 자동 저장, 이어하기/처음부터, 결과 근거를 제공한다.
- MBTI 결과는 `진단이 아닌 성격 참고 콘텐츠`로 고지하고 장식 이모지·그라데이션을 제거한다.
- O/X 퀴즈는 선택 후 정오·해설을 색상 외 텍스트와 아이콘으로 표시한다.
- 퀴즈 완료 커밋과 보상 hook은 멱등을 유지하며 복기 재진입에서 중복 지급하지 않는다.
- 운세는 `재미로 보는 콘텐츠` 라벨을 상단에 두고 건강 진단과 시각적으로 분리한다.
- 운세의 럭키 간식·장소는 실제 추천/지도 계약이 없는 한 행동 CTA로 만들지 않는다.
- 뉴스는 출처, 발행일, 외부 링크를 먼저 표시하고 원문 열기 실패 복구를 제공한다.
- 리워드는 실제 교환·재고·결제 계약 전까지 `오픈 예정`과 포인트 조회만 표시한다.
- 포인트는 적립 사유·시각·증감·잔액의 이력을 제공한다. 정책 확정 전에는
  `현재 적립 포인트는 유효기간이 없으며 교환 기능은 준비 중`으로 고정한다.
- W5 리워드 화면은 잔액 바로 아래 `적립 내역` 행에서 이력으로 진입한다.

### 5.8 Home — 기획만, 구현 잠금

- 첫 화면의 우선순위는 대표 반려동물 상태 → AI 분석 시작 → 건강/기록 빠른 행동이다.
- MBTI·퀴즈·운세·뉴스·리워드는 핵심 행동 아래 보조 모듈로 제한한다.
- 이미 사용자에게 익숙한 여권 카드와 navy 브랜드 영역은 별도 승인 없이 바꾸지 않는다.
- 카드마다 서로 다른 그림자·그라데이션·이모지를 쓰지 않고 공통 표면과 아이콘을 사용한다.
- 실패한 보조 모듈 하나가 전체 Home을 막지 않도록 영역별 오류와 재시도를 제공한다.

## 10. 완료 판정

- 기능 테스트 통과만으로 UI/UX 완료로 판정하지 않는다.
- 각 화면의 정상·로딩·빈 상태·오프라인·권한·부분 실패·세션 만료·파괴적 행동을 확인한다.
- 게시글 작성, 커뮤니티 글, 댓글, 팔로우, 좋아요, 저장, 메시지, 반려동물 변경,
  건강 기록, MBTI, 퀴즈, 운세, 뉴스 링크를 실제로 수행한다.
- OAuth·푸시·실제 두 계정 상호작용은 사용자가 QA 자격증명을 입력한 실기기 검증을
  자동 테스트와 별도로 통과해야 한다.
- blocker/high, 보호 계약 변경, manifest 밖 수정, 비밀 노출, 신규 실패가 있으면 중단한다.

## 11. Claude 교차검토와 최종 합의

Claude Opus 5는 v1을 3회 독립 관점으로 검토하고 `changes_required`를 판정했다.
Codex는 지적을 재검증해 다음을 v2에 수용했다.

- CTA `#2F6399` 복귀와 라이트/다크 토큰 B0 선행
- 레거시 visibility fail-closed + 소유자 재설정
- 반려동물 soft delete 30일 유예 + 대표 직접 재선택
- 위치 미수집 + 장소 UI 미노출
- 세션 만료 draft 저장·복원, 채팅 backfill, 0마리 전용 상태
- 80개 presentation 화면의 배치·근거·완료 조건 매핑
- 장식 이모지·그라데이션·그림자 정리를 각 배치 완료 조건으로 이동

남은 항목까지 v2에 고정한 뒤 Claude가 다시 판정한 최종 결과는
`approved / blocker 0 / high 0`이다. 이 승인은 기획 계약에 한정되며 구현을
자동 승인하지 않는다.

Claude 원문 요약과 Codex 판정은
`docs/reviews/claude/2026-08-04-full-app-planning-review-result.md`에 기록한다.
외부 검토에 비밀 파일, Firebase plist, 환경변수, 사용자 데이터, 로그,
빌드 생성물은 포함하지 않았다. Home·AI 분석 결과 구현 잠금은 유지한다.
