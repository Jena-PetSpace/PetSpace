# MY 탭 전체 기획·코드 감사

- 작성일: 2026-07-14
- 작성: Codex, Claude Opus 4.8 독립 검토
- 상태: 사용자 5화면 목업 승인 및 MY Core 1 12파일 구현 완료, Codex·Claude Opus 4.8 `approve`, blocker/high 0, 실기기 검증 대기
- 대상: `MY → 피드 → 건강관리 → AI 분석 → 홈` 탭 순서 중 첫 번째 MY 탭
- 구현 게이트: 정확한 12파일 구현·자동 검증·양쪽 리뷰는 완료했다. `docs/work-orders/2026-07-14-uiux-my-core-1.md`의 실기기 체크를 통과하기 전에는 이 범위를 사람 검증 완료로 동결하지 않는다.

## 1. 사용자 결정과 범위

1. 다크모드 전환·완성도 개선은 이번 MY 탭 범위에서 제외하고 공통 백로그로 이동한다.
2. 하단 5탭의 구조·아이콘·색·배지·중앙 버튼은 수정하지 않는다.
3. MY 완료는 반려동물 관리 화면만이 아니라 MY 진입 화면, 모든 설정 메뉴, 각 하위 화면, 빈 상태·오류·파괴적 작업까지 검토한 뒤 판정한다.
4. AI 분석 히스토리는 MY 설정의 진입·복귀 계약까지만 MY 범위에서 검토한다. `features/emotion/presentation/**`의 전체 UI 재설계는 AI 분석 탭 차례와 별도 사용자 승인 전까지 금지한다.
5. 법무·개인정보·운영 약속·DB/API 의미는 UI 목업으로 새로 만들거나 자동 변경하지 않는다. 불일치는 먼저 사람 결정 항목으로 올린다.

## 2. 실기기 캡처 판정

제공된 캡처 5장은 이전 MY 반려동물 Visual Polish의 실기기 증거로 사용했다.

| 화면 | 판정 | 남은 항목 |
|---|---|---|
| 반려동물 관리 1마리 | 시각 위계 개선 확인 | 카드의 긴 품종·접근성은 회귀 점검 유지 |
| 등록 기본 정보 | 밀도·사진 영역·단계 위계 개선 확인 | 키보드·권한 거부·150% 글자 크기 실기기 확인 필요 |

## 4. 핵심 발견과 제품 판단

### 4.1 신뢰를 떨어뜨리는 고정·가상 데이터

`MyProfileHeader`는 다음 정보를 실제 프로필/리워드 데이터와 연결하지 않고 보여준다.

- 이메일 로컬 파트로 만든 `@handle`
- `레벨 1 견주`
- `반려동물 이야기를 들려주세요`
- `0 P`

프로필 편집은 bio를 실제 저장하지만 헤더는 그 값을 읽지 않는다. 리워드 진입을 숨긴 상태에서 포인트와 뱃지를 먼저 강조하는 것도 제품 우선순위가 모순된다.

**권고:** 실제 단일 데이터 계약을 만들기 전까지 레벨·포인트를 숨기고, 실제 닉네임·bio·게시글/팔로워/팔로잉만 신뢰도 있게 보여준다. 뱃지와 리워드는 함께 출시 가능한 시점에 한 묶음으로 재검토한다.

### 4.2 개인정보 설정은 현재 사용자 기대를 충족하지 않는다

`PrivacySettingsPage`의 비공개 계정·온라인 상태·이메일 검색 허용은 `SharedPreferences`에만 저장된다. 서버 조회/RLS/검색/온라인 상태 동작을 바꾸지 않는다. 또한 back fallback은 제거된 `/settings`를 가리킨다.

**권고:** 세 스위치를 지금 설정 허브에 연결하지 않는다. 차단 목록만 독립 기능으로 노출할지, 서버 개인정보 계약을 구현한 뒤 전체 화면을 공개할지 먼저 결정한다.

### 4.3 알림 설정 저장과 실제 푸시 발송이 분리되어 있다

앱은 `notification_preferences`를 저장하지만 현재 DB trigger와 `send-push-notification` Edge Function은 해당 선호도를 조회하지 않고 활성 기기에 전송한다. 채팅 스위치는 서버 컬럼 없이 로컬에만 저장된다.

**권고:** 알림 UI 목업보다 먼저 알림 타입 매핑과 발송 차단 지점을 서버 단일 계약으로 확정한다. 사용자가 끈 알림이 계속 오는 상태에서 UI만 다듬는 것은 금지한다.

### 4.4 법무·운영 문구가 실제 동작과 충돌한다

커뮤니티 가이드라인에는 다음 검증 필요 항목이 있다.

- `영업일 기준 24시간 이내` 검토/조치 약속
- 차단 상대가 내 게시물을 볼 수 없다는 단정
- 탈퇴 시 모든 데이터가 즉시 영구 삭제된다는 문구
- 현재 화면 명칭과 다른 `[내 정보 → ...]` 동선
- 시행일이 공용 법무 정본과 다름

도움말의 `support@petspace.app`과 법무 정본·앱 설정에 쓰이는 연락 채널 중 무엇이 실제 운영 가능한 단일 정본인지 사람 확인이 필요하다.

**권고:** 새 법률 문구를 AI가 작성하지 않는다. 운영 가능한 SLA·지원 채널·차단/탈퇴 실제 동작을 사람이 확정하고 법무 정본을 승인한 뒤 화면은 그대로 렌더링한다.

### 4.5 반려동물 상세는 시각과 의미 모두 별도 작업이다

- 300px hero는 정보 밀도를 낮추고 사진이 없을 때 거대한 파란 면을 만든다.
- 분홍/파랑/갈색 의미색과 강한 CTA/outline이 새 MY settings·pet editor와 다르다.
- `함께한 날`이 실제 입양일이 아니라 DB 생성일(`createdAt`) 기준이다.
- 생년월일이 없으면 나이 미상인데 등록일은 오늘로 보여 사용자에게 사실처럼 읽힌다.
- 삭제 시 관련 데이터 전체 삭제 문구는 배포된 DB cascade 검증과 함께 확인해야 한다.

**권고:** 사용자에게 확정된 사실만 표시한다. 입양일 데이터가 없으면 `등록한 날`로 바꾸거나 해당 항목을 숨기고, 상세의 1차 행동은 기록 보기/정보 관리의 사용자 목적을 재정의한 뒤 정한다.

### 4.6 공개 반려동물 프로필은 현재 외부 사용자 흐름이 성립하지 않는다

- pets RLS는 `auth.uid() = user_id`인 본인 조회만 허용한다.
- 따라서 타인이 `/pet/public/:petId`를 열면 반려동물을 찾지 못한다.
- 공유 링크는 `https://petspace.app/pet/:id`지만 앱 라우트는 `/pet/public/:petId`다.
- 감정 이력도 본인 전용 RLS라 타인에게 분석 횟수/기록을 공개할 수 없다.
- `보호자 팔로우`인데 화면 명칭과 통계는 반려동물 프로필처럼 보여 대상이 모호하다.

**권고:** 공개 범위, 공개 필드, 보호자/반려동물 팔로우 대상, 분석 정보 비공개 원칙, 딥링크 정본을 먼저 결정한다. 이 결정 전에는 공개 프로필 UI 구현을 진행하지 않는다.

## 5. MY 탭 권장 정보 구조

MY의 역할을 세 축으로 제한한다.

1. **나의 정체성:** 실제 프로필, 게시글/팔로워/팔로잉, 프로필 편집
2. **나의 보관함:** 내 게시글, 저장한 게시글/컬렉션, 명확한 빈·오류 상태
3. **나의 관리:** 반려동물, 알림, 차단, 도움말, 법무, 계정 안전

AI 분석의 상세 리포트는 AI 탭, 피드 탐색/작성 경험은 피드 탭이 정본이다. MY에서는 내 기록의 요약·진입·복귀만 제공한다.

1. MY 메인: 실제 데이터만 쓰는 프로필·통계·내 글/저장 탭
2. 반려동물 상세: 사진 있음/없음과 미상 데이터의 사실 기반 표현
3. 설정 허브: 사용 가능한 메뉴와 준비되지 않은 메뉴가 섞이지 않는 구조
4. 저장 보관함: 컬렉션 채택 여부가 반영된 loaded/empty/error
5. 프로필 편집: 사진·닉네임·소개·저장 상태의 통일된 폼

알림·개인정보·탈퇴는 MY-A 계약이 확정되기 전까지 목업에서 기능 완료처럼 표현하지 않는다.

### MY-C — 승인된 3~5화면 단위 구현

한 번에 3~5개 핵심 화면만 정확한 manifest로 구현한다. Codex 구현 초안과 Claude 리뷰, analyze/test/diff/protected hash, 사용자 실기기 승인을 통과한 뒤 동결한다.

### MY-D — 후속 설정·지원·공개 프로필

MY-A에서 서버/법무/운영 계약이 확정된 항목만 별도 manifest와 목업으로 진행한다.

## 7. 제안 manifest 경계

목업 승인 전에는 파일을 확정하지 않는다. 현재 예상 후보는 아래와 같으며 Flutter 변경 권한을 뜻하지 않는다.

- MY 메인: `my_page.dart`, `my_profile_header.dart`, `user_badges_section.dart`, 숨김 상태인 `my_pet_summary_section.dart`와 MBTI 요약의 노출 결정
- 저장 정본: `my_saved_posts_page.dart` 또는 `my_page.dart` 중 하나만 채택
- 반려동물 상세: `pet_detail_page.dart`
- 프로필 편집: `profile_edit_page.dart`
- 설정 허브: `my_settings_page.dart`
- 라우트/중복 청산: `app_router.dart`, 미연결 MY 페이지·widget은 별도 승인
- 서버/DB/법무/운영 변경: MY UI manifest와 분리하고 사람 승인 필수

## 8. 테스트·완료 조건 초안

- loaded/loading/empty/error/offline을 빈 상태와 구분
- 실제 데이터만 노출하며 고정 레벨·포인트·소개 금지
- 저장 탭과 컬렉션의 단일 정본 및 복귀 위치 보존
- 반려동물 사진 없음·생년월일 없음·품종 없음·긴 이름에서 사실/레이아웃 보존
- 프로필 텍스트 저장·이미지 부분 실패·재시도·이탈 확인
- 알림 off가 실제 push 발송을 막는 서버 검증 없이는 완료 판정 금지
- 개인정보 스위치가 실제 접근/검색 동작을 바꾸는 E2E 없이는 노출 금지
- 탈퇴 30일 soft delete·복구·영구 삭제 문구와 E2E 일치
- 법무 시행일·연락처·지원 채널 단일 정본
- 하단 5탭, home, emotion 보호 경로 불변
- commit/merge/push/deploy/운영 DB 작업 없음

## 9. 현재 결론

MY 반려동물 관리·등록·수정의 시각 개선은 실기기에서 유의미하게 확인됐다. 그러나 MY 탭 전체는 아직 완료 상태가 아니다. 다음 구현 전에 MY-A의 기능·개인정보·법무 계약을 확정하고, 합의된 5개 대표 목업으로 MY 전체 방향을 먼저 보여주는 것이 가장 안전하다.

## 10. Claude Opus 4.8 독립 검토 결과

- 최종 판정: `accept`
- blocker: 0
- high: 알림 선호도 미집행, 커뮤니티 가이드와 실제 동작 충돌, 공개 반려동물 프로필 미성립
- medium: 고정 프로필/포인트, 오류와 빈 상태 혼합, 로컬 전용 개인정보 스위치, `함께한 날`의 데이터 의미 오류
- low: 숨겨진 MBTI·반려동물 요약 섹션 인벤토리 누락 — 본 문서에 반영 완료
- 계약 게이트: 승인. 서버·법무·운영·RLS 변경은 사람 결정 전 자동 구현 금지
- 합의 목업 순서: MY 메인 → 반려동물 상세 → 설정 허브 → 저장 보관함 → 프로필 편집

따라서 이 문서는 MY 탭 목업 설계의 Codex·Claude 합의 기준으로 사용한다. 목업과 정확한 구현 manifest는 사용자 최종 승인 전까지 Flutter 코드 변경 권한을 부여하지 않는다.
