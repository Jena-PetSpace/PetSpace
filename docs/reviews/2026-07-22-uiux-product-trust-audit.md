# PetSpace UI/UX 제품 신뢰도 재감사

> 기준 SHA: `c49a8c4`
> 관점: 모바일 앱 프론트엔드·프로덕트 디자인 10년차 수준의 출시 품질
> 방식: iPhone 17 Simulator 실화면 + 코드·접근성 트리 + 기존 692개 테스트 근거
> 상태: 방향 논의 전 초안, 구현 금지

## 1. 결론

기능은 많은 편이지만 화면이 하나의 제품 언어로 묶이지 않아 신뢰도가 떨어진다. 가장 큰 원인은 개별 카드의 미감이 아니라 다음 네 가지 시스템 문제다.

1. 루트 화면과 하위 작업 화면의 내비게이션 계층이 구분되지 않는다.
2. 타이포·간격·카드·입력·칩·아이콘 규칙이 화면마다 다르다.
3. 옅은 회색, 작은 글자, 큰 빈 공간으로 정보 위계와 가독성이 약하다.
4. 빈 상태·로딩·오류·권한 상태가 범용 아이콘과 문구로 반복되어 제품 고유성이 없다.

따라서 화면별 색상 보정부터 시작하면 재작업한다. 먼저 `Navigation + Visual Foundation`을 확정하고, 이후 사용자 여정 순서대로 화면을 다시 설계해야 한다.

## 2. 실화면 감사 범위

이번 패스에서 직접 확인한 화면:

- 홈 기본 진입과 전역 하단 내비게이션
- 건강관리, 기록 필터, 기록 카드, 건강 변화, 기록 추가 시트
- 피드·커뮤니티, 검색, 게시물 상세, 댓글, 미디어 뷰어, 게시글 작성
- MY 메인, 프로필 편집, 설정, 반려동물 관리, 반려동물 등록, 알림 설정
- 채팅 목록 빈 상태, 새 채팅 빈 상태

인증·온보딩은 현재 로그인 세션을 보존하기 위해 로그아웃하지 않고 코드·라우트·테스트 기준으로 검토했다. Apple/Google/Kakao 실제 화면은 별도 계정 QA가 필요하다.

## 3. 현재 UI 품질 점검

| 기준 | 현재 | 출시 목표 | 핵심 문제 |
|---|---:|---:|---|
| 정보 위계 | 5/10 | 8/10 | 제목·본문·보조 텍스트 대비가 약함 |
| 브랜드 일관성 | 4/10 | 8/10 | 화면마다 다른 카드·칩·아이콘 문법 |
| 내비게이션 명료성 | 3/10 | 9/10 | 하위 화면에도 하단 탭과 중앙 FAB가 남음 |
| 입력 폼 완성도 | 5/10 | 8/10 | 큰 빈 공간, 약한 필수/선택 구분, 기본 TextField 인상 |
| 상태 디자인 | 4/10 | 8/10 | 큰 범용 아이콘 + 짧은 문구의 반복 |
| 접근성 | 4/10 | 9/10 | 이름 없는 아이콘·탭·선택 칩, 옅은 텍스트 |
| 제품 신뢰감 | 4/10 | 8/10 | 템플릿을 이어 붙인 듯한 화면 간 단절 |

점수는 기능 완성도가 아니라 사용자가 받는 시각적·상호작용 신뢰도를 평가한 것이다.

## 4. “바이브 코딩처럼 보이는” 구체적 신호

### 4.1 내비게이션

- 게시글 작성, 프로필 편집, 설정, 새 채팅 같은 집중 작업 화면에서도 하단 탭이 보인다.
- 중앙 paw FAB가 하위 화면의 저장 버튼·콘텐츠·탭을 시각적으로 침범한다.
- 현재 선택 탭과 화면 제목이 일치하지 않는 순간이 생긴다. 예: 새 채팅 화면인데 홈 탭이 선택돼 있다.
- 풀스크린 작업, 상세, bottom sheet의 계층 기준이 일관되지 않다.

### 4.2 타이포와 대비

- 섹션 라벨과 보조 설명이 지나치게 작고 옅다.
- 중요한 날짜·상태와 장식적인 정보가 비슷한 위계로 보인다.
- 한 화면 안에서 굵기·크기 단계가 많지만 역할이 명확하지 않다.

### 4.3 컴포넌트

- 같은 선택 기능이 Tab, pill chip, segmented button, outline card로 제각각 구현돼 있다.
- 카드 radius, border, background tint, shadow가 화면별로 달라 조립식 인상을 준다.
- Material 기본 아이콘, SVG, paw, 문서 아이콘이 하나의 family처럼 보이지 않는다.
- 입력 필드는 흰 사각형을 반복하고 필수/선택·검증·도움말 위계가 약하다.

### 4.4 콘텐츠와 상태

- 빈 화면이 넓은 공간 중앙의 큰 아이콘 하나에 의존한다.
- 비어 있는 이유, 사용자가 얻을 가치, 바로 할 수 있는 행동이 연결되지 않는다.
- 피드의 사진·작성자·캡션·태그·감정 상태·반응이 한 카드 안에서 경쟁한다.
- 건강 화면은 기록, 다음 일정, 변화 추이, AI CTA의 우선순위가 불명확하다.

## 5. 재기획 우선순위

### P0 — Navigation + Visual Foundation

앱 전체에 먼저 적용할 계약:

- 루트 탭에만 하단 내비게이션 표시
- 작성·편집·설정·상세·채팅 같은 하위 화면에서는 하단 탭과 중앙 FAB 제거
- 중앙 AI를 일반 5번째/가운데 탭으로 둘지, 작은 root-only 강조 버튼으로 둘지 사용자 결정
- 8pt grid, 4단계 radius, 3단계 border/elevation, 단일 outline icon family
- type scale을 Display / Title / Body / Label / Caption 5역할로 축소
- surface는 warm off-white + white, brand navy는 제목·핵심 action에만 사용
- root header, task app bar, form section, list row, empty/error state 정본 컴포넌트 확정

이 단계가 확정되기 전에는 개별 화면 구현을 시작하지 않는다.

### P1 — 인증·온보딩 “첫 3분”

첫인상과 개인정보 신뢰를 결정하는 흐름이다.

- Splash → 소개 → 로그인 선택 → 약관 → 프로필 → 첫 펫 등록 → 완료
- 소셜 로그인 버튼의 플랫폼 규칙과 브랜드 가이드 준수
- `실명`처럼 느껴지는 입력을 `닉네임` 계약으로 정리할지 결정
- 약관 저장 실패를 숨기지 않고 상태 보존·재시도 제공
- 사진 선택·업로드·권한 실패를 한 문장 SnackBar가 아니라 폼 상태로 표현
- 일러스트는 온보딩에만 제한적으로 사용하고 나머지는 실제 콘텐츠 중심

### P2 — 반려동물 Identity + MY

PetSpace가 일반 SNS가 아니라 “내 반려동물 기반 서비스”라는 점을 가장 명확히 보여야 한다.

- MY 상단을 사람 프로필만이 아니라 대표 반려동물 identity와 연결
- 반려동물 관리 카드의 품종·나이·성별·대표 상태 위계 재정리
- 등록 화면의 진행률, 사진, 필수 정보, 종 선택을 하나의 onboarding pattern으로 통일
- 아이콘 전용 내 글/저장 탭을 텍스트 탭으로 변경
- 빈 상태는 “게시물이 없음”보다 첫 공유의 가치와 CTA를 설명

### P3 — Feed + Create + Social trust

- 피드 카드에서 작성자, 캡션, 사진, 감정 정보, 반응의 우선순위를 다시 배치
- hashtag pill 남발을 줄이고 태그는 보조 메타데이터로 처리
- 사진 위주 피드 게시물과 커뮤니티 텍스트 글의 visual grammar를 분리
- 게시글 작성은 하단 탭 없는 task screen으로 전환
- pet 선택, 사진 최대 10장, 캡션, 공개 범위, 위치, 임시저장을 위에서 아래 한 흐름으로 정리
- 신고·차단·좋아요·저장 성공/실패 피드백을 같은 interaction pattern으로 통일
- 현재 `is_private` 값은 K1 SELECT 정책과 직접 피드 조회에서 audience를 강제하지 않으므로 `팔로워만` 선택지는 보안 계약이 완성될 때까지 숨긴다.
- 현재 picker와 저장 계약은 사진만 지원하므로 동영상 업로드를 화면에서 약속하지 않는다.

### P4 — Health care clarity

- 최상단 우선순위를 `다음 케어`로 둘지 `최근 기록`으로 둘지 확정
- 기록 유형은 동일한 아이콘·색 규칙을 쓰고 색만으로 구분하지 않음
- 빈 기록 저장을 방지하고 필수/선택을 시각적으로 명확히 함
- 기록 추가는 root FAB 대신 명확한 CTA 또는 app bar action 사용
- 5종 입력은 긴 bottom sheet 대신 하단 탭 없는 full task screen으로 전환
- 예방접종 신규 입력은 백신 종류를 필수로 검증하되 기존 빈 값 기록의 조회·편집 호환 유지
- 변화 추이는 데이터가 있을 때만 확장하고, 없을 때 AI CTA가 화면을 지배하지 않게 함
- 의료 진단처럼 보이지 않는 안전한 문구 유지
- 자동 예정일 알림은 운영 연결 전까지 `준비 중`으로 표시하고 5초 기기 테스트와 명확히 분리

### P5 — Chat + Notifications + Settings

- 새 채팅의 빈 상태에 검색 외에 `팔로우할 사용자 찾기` 등 명확한 다음 행동 제공
- 채팅 상세는 메시지·날짜·전송 실패·이미지 업로드 상태를 메신저 수준으로 정리
- 채팅 사진은 한 번에 최대 10장으로 제한하고 실패한 동일 선택의 재전송 계약 유지
- 관리자 이름·사진·초대와 일반 참여자의 읽기 전용 권한을 구분하고, 저장 계약이 없는 멤버 강제 퇴장·방별 알림은 노출하지 않음
- 설정은 native disclosure list로 단순화하고 destructive action을 별도 섹션으로 분리
- 알림 설정의 master switch와 하위 switch 종속 상태를 시각적으로 표현
- 하위 화면에서는 전역 탭을 제거해 작업 집중도 확보

### P6 — State system + polish

- loading skeleton, empty, offline, permission denied, destructive confirmation, success toast 정본화
- 150%/200% text scale, VoiceOver, dark mode, reduce motion 검증
- 화면 전환·저장 성공·선택 변경에 절제된 150~220ms motion과 haptic 사용
- 기존 휴면/중복 화면은 재디자인 전에 유지/삭제 결정

### 별도 보호 범위

기존 지시에 따라 홈·AI 분석 콘텐츠 재설계는 별도 승인 전 보류한다. 다만 전역 Navigation Foundation을 바꾸면 두 탭의 shell·app bar·safe area는 회귀 대상에 포함한다.

## 6. 작업 순서

1. 디자인 방향과 내비게이션 원칙 사용자 합의
2. root/task 공통 shell + 핵심 component 목업
3. P1~P5의 모든 주요 상태 목업을 화면별로 사용자 확인
4. 승인된 화면만 exact work order·file manifest로 전환
5. wave별 구현과 자동·시뮬레이터 QA
6. 마지막에 실제 계정 2개로 create/follow/like/comment/save/message/report/block 전수 E2E

## 7. 구현 전 중단 조건

- 목업이 승인되지 않은 화면
- 홈·AI 콘텐츠 변경이 필요한 경우
- 하단 탭 순서·중앙 AI entry의 사용자 결정이 없는 경우
- 운영 DB/RPC·Edge·APNs 변경이 필요한 경우
- 실제 사용자 데이터 삭제·신고·차단·계정 변경이 필요한 테스트

해당 조건에서는 Flutter 구현이나 외부 상태 변경을 진행하지 않는다.
