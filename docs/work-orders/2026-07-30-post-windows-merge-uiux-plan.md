# PetSpace Windows→Mac 병합 후 UI/UX 개선 기획 v3

- 작성일: 2026-07-30
- 대상 브랜치: `mac-ios-release`
- 병합 기준: `021f424e3bd928fb56b6daa558d4961184f51772`
- 병합 결과: `02f74e50d645a2e4eb29cb0d4ac735ff40d39445`
- 상태: 사용자 방향 승인 완료, Wave 0~4 구현 후 remediation 검증 중
- 구현 게이트: 후속 사용자 지시와 승인 manifest 범위 안에서만 수정

## 1. 병합 및 검증 결론

Windows 브랜치의 18개 커밋은 Mac HEAD의 직계 후손이어서 충돌 없이
fast-forward로 반영됐다. iOS 시뮬레이터 점검 과정에서 아래 보완을 적용했다.

- iOS Kakao 지도 준비 상태와 실패 콜백 호환
- 지도 준비 timeout과 실패 후 플랫폼 뷰 재생성
- 장소 선택 화면의 동일 timeout·재시도 복구
- AI 분석 기록 오류의 서버 원문 노출 제거
- Kakao 키워드 검색의 업종 오탐 필터
- 지도·오류 계약 회귀 테스트 추가

최종 검증:

- 지도 플러그인 테스트 9개 통과
- 집중 회귀 테스트 29개 통과
- 전체 Flutter 테스트 899개 통과
- `flutter analyze --no-pub` 이슈 0건
- `flutter build ios --release --no-codesign --no-pub` 성공
- `git diff --check` 통과
- 비밀 파일은 ignored·untracked 상태 유지

남은 외부 게이트:

- iOS Kakao Native 지도 인증이 401을 반환한다.
- REST 장소 검색, 거리, 상세, 저장은 정상이다.
- Kakao Developers의 iOS 플랫폼 번들 ID와 Native app key 등록을 확인한 뒤
  실제 지도 렌더·시트 resize·카메라 이벤트를 다시 검증해야 한다.
- Apple 로그인은 서명 실기기 빌드에서 별도 검증해야 한다.

Claude와 Codex의 기획 교차 검토는 UX 리드, Flutter 아키텍트, 백엔드·심사
안전의 세 관점으로 수행했다. 1차 결과는 `CHANGES_REQUIRED`였고, v2에는
지적된 색 대비, 카드 경계, AI 비진단 표현, 지도 리스트 대체, 신고·차단,
건강 일정 단일 기준, 세션 만료, 최초 상태, Dynamic Type 및 작업 순서를
반영했다. 실제 목업 5장을 첨부한 2차 Claude 리뷰도 `CHANGES_REQUIRED`였으며,
v3에서는 작성 IA, AI 관찰 출처, 감정 결과, 오류 상태 분리, 지도 성공·위치
선택, 위치 공개 기본값, 펫 삭제 규칙을 보완하고 목업을 8장으로 확장했다.

## 2. 디자인 원칙

1. 한 화면에는 하나의 명확한 주요 행동만 둔다.
2. 페이지 배경은 중립 캔버스, 콘텐츠는 흰색 또는 아주 옅은 파란 surface를
   사용한다. 진한 네이비는 브랜드 헤더·핵심 요약 영역에만 제한한다.
3. 앱바 제목은 기본적으로 왼쪽 정렬하고, 전체 화면 작업·모달만 중앙 정렬한다.
4. 카드 안에 카드를 반복하지 않는다. 카드는 흰색 surface와 `#E5E8EC` 1px
   outline으로 정의하며, 임의 그림자나 surface 중첩은 사용하지 않는다.
5. 빈 상태는 장식 이모지·대형 일러스트 없이 제목, 한 문장, CTA로 끝낸다.
   최초 온보딩형, 필터 초기화형, 오류 재시도형의 세 변형을 둔다.
6. 본문은 14sp 이상, 터치 영역은 44pt 이상, 상태는 색 외 텍스트·아이콘도
   함께 제공한다.
7. 고정 하단 CTA는 콘텐츠를 가리지 않고 Safe Area를 한 번만 소유한다.
   리스트 하단 패딩은 `CTA 높이 + 하단 Safe Area + 16pt` 이상으로 한다.
8. 성공·빈 상태·오류·로딩은 모든 기능에서 같은 문법을 사용한다.
9. Dynamic Type은 foundation 제약으로 다룬다. 핵심 흐름은 200% 배율에서
   잘림 없이 reflow·scroll되고, 더 큰 접근성 배율에서도 행동이 사라지지
   않아야 한다.
10. 다크 모드는 이번 구현 범위에서 제외하고, 라이트 모드 완성 후 별도
    디자인 토큰 검토로 분리한다.

기본 토큰 제안:

| 역할 | 값 |
|---|---|
| Brand deep | `#1E3A5F` |
| Primary CTA·텍스트 액센트 | `#2F6399` |
| 선택·차트·비텍스트 액센트 | `#3F7DBA` |
| Pale blue surface | `#EEF5FB` |
| Page canvas | `#F7F8FA` |
| Auth canvas | `#F8F6F2` |
| Card surface | `#FFFFFF` |
| Card outline | `#E5E8EC`, 1px |
| Success | `#217A4A` + 텍스트·체크 아이콘 |
| Caution | `#8A5A00` + 텍스트·주의 아이콘 |
| Destructive | `#B42318` + 확인 단계 |
| 기본 radius | 12 |
| 섹션 간격 | 24 |
| 카드 내부 간격 | 16 |

WCAG 계산 재확인 결과 `#2F6399`와 흰색의 대비는 6.24:1, `#1E3A5F`와
흰색은 11.50:1이다. 기존 `#3F7DBA`와 흰색은 4.33:1이므로 작은 CTA
텍스트 색이나 흰 글자 CTA 배경에는 쓰지 않고 비텍스트 상태에만 사용한다.

## 3. 우선순위

### P0 — 릴리스·신뢰도

- Kakao iOS 401 외부 설정 해소 후 실제 지도 성공 경로 검증
- 지도 실패 시 검색·상세·저장을 유지하는 리스트 전용 대체 모드 제공
- 플레이스 화면에 명시적 뒤로가기 제공
- 로그인·회원가입·비밀번호 재설정의 배경과 하단 CTA surface 통일
- 오류·로딩·빈 상태와 세션 만료의 공용 패턴 적용
- 펫 0마리 최초 상태와 대표펫 변경·삭제 상태 정의
- 건강 화면의 일정 개수와 실제 빈 상태를 하나의 selector에서 계산

### P1 — 핵심 탭 정보 구조

- 홈: 여권 카드의 미세 정보 축소, AI 감정·건강 행동을 첫 화면 핵심으로 승격
- 건강: 다음 케어 → 기록 추가 → 최근 기록 → 변화 순으로 재구성
- AI 분석: 분석 종류·반려동물·사진·실행의 4단계 단순화
- 피드·커뮤니티: 미디어 중심 피드와 텍스트 중심 커뮤니티의 시각 문법 분리
- 피드·커뮤니티: 게시물·댓글·사용자 신고 진입점과 차단 필터링 동작 고정
- 피드 작성과 커뮤니티 작성은 별도 화면으로 분리하고 공용 draft 계층만 공유
- 작성: 이탈 확인과 로컬 임시 저장으로 입력 내용 손실 방지
- MY: 프로필·통계·대표 반려동물을 한 덩어리로 읽히게 정리

### P2 — 작성·탐색 흐름

- 게시글 작성: 위치 섹션이 고정 CTA에 가리지 않도록 스크롤·Safe Area 검증
- 커뮤니티 글쓰기: 분류·제목·본문·등록의 밀도와 오류 보존 안내 정리
- 검색: 사용자·게시글·태그·장소 결과의 필터와 빈 상태 통일
- AI 기록: 대표 반려동물 자동 선택, 필터·흐름 빈 상태의 중첩 surface 축소

### P3 — 보조 화면과 운영성

- 설정·알림·개인정보·차단 관리: 현재 그룹형 목록을 공용 컴포넌트로 고정
- 반려동물 관리: 대표/기타 목록을 단일 리스트 문법으로 단순화
- 프로필·팔로워·팔로잉: 검색, 빈 상태, 오류, 페이지네이션 통일
- 채팅·알림: 읽음 상태, 실패 재시도, 네트워크 복구 상태를 같은 패턴으로 표시
- 200% 글자·320×568·iPad split view 시각 회귀 추가

## 4. 탭별·페이지별 기획

### 홈

- 첫 화면 순서: 브랜드 헤더 → 반려동물 요약 → 오늘의 AI 체크 → 빠른 기능 →
  최근 활동/콘텐츠.
- 여권의 실제 가치인 반려동물 식별은 유지하되 국가코드·여권번호 등 장식성
  마이크로카피는 축소한다.
- 감정 분석과 건강 분석을 동일한 무게의 두 CTA로 제시한다.
- 광고·핫이슈·매거진은 핵심 행동 이후에 배치한다.

### 건강

- 선택 반려동물은 한 줄 selector로 고정한다.
- 다음 일정이 없으면 개수 배지를 표시하지 않는다.
- 기록 유형 필터는 가로 스크롤 가능성을 시각적으로 드러낸다.
- 건강 기록 작성의 유형·날짜·상태는 필수/선택 라벨을 한 규칙으로 통일한다.
- 데이터가 쌓이면 체중·식사·배변·투약을 선택해 보는 한 개의 추이 차트를 둔다.
- 일정 배지·목록·빈 상태는 공용 `health schedule selector` 결과만 소비하며
  홈·건강·펫관리 화면에서 개별 계산하지 않는다.

### AI 분석

- 감정/건강 segment, 반려동물 selector, 사진 영역, 분석 버튼만 1차 화면에 둔다.
- 촬영 가이드는 상세 페이지나 펼침 영역으로 분리한다.
- 분석 전에는 예측이나 점수처럼 오해할 수 있는 요소를 보여주지 않는다.
- 기록 화면은 대표 반려동물을 기본 선택하고, 7/30/90일은 데이터가 있을 때만
  차트 강조를 사용한다.
- 건강 분석 결과는 진단명이 아닌 “확인된 신호·가능성” 단계로 표현한다.
- AI 관찰은 업로드 사진에서 확인 가능한 시각 정보로만 제한한다. 식욕,
  활동량, 구토, 기간 변화처럼 사진만으로 알 수 없는 정보는 “보호자 기록”에
  분리하고 AI가 관찰한 것처럼 쓰지 않는다. 이번 Wave에서는 새 보호자 기록
  입력·스키마를 AI에 추가하지 않고 기존 건강 기록과의 연동을 후속 기획으로
  분리한다.
- 결과에는 사전 확인 목적 안내, 정성적 확신도, 관찰 행동, 수의사 상담 CTA를
  함께 제공하고 전체 모델 정확도를 개별 결과 신뢰도처럼 병기하지 않는다.
- 권장 행동은 처방성 케어 지시나 특정 대기 시간을 쓰지 않고, 보호자가
  확인할 관찰 체크리스트와 수의사 상담 유도로 한정한다.
- Grad-CAM은 기본 비노출이며 “왜 이렇게 판단했나요?” 펼침 안에서
  “모델이 참고한 영역이며 심각도를 뜻하지 않음”을 평문으로 설명한다.
- 감정 결과는 “보리가 행복해요”처럼 감정을 단정하지 않고 “편안한 표정
  신호가 관찰돼요”처럼 라벨+사진 기반 관찰 문장으로 표현한다.
- AI 기록은 별도 목업으로 분리한다. 반려동물·기간 필터, pagination,
  메모 보기/편집 모달, 저장·폐기 확인과 글자 수 상한을 함께 설계한다.
- AI 기록과 결과 상세은 push 화면이므로 명시적 뒤로가기를 둔다. 이미 저장된
  상세에서는 “기록에 저장” 대신 “메모 추가/수정”과 “공유”만 제공한다.
- 상태 단계는 색만으로 표현하지 않고 안전/주의/확인 필요 라벨과 아이콘을
  함께 쓴다. 네이비를 심각도 색으로 사용하지 않는다.
- 결과 상태는 “특이사항 없음 / 관찰 권장 / 확인 필요”의 세 정성 단계로
  고정하고 정상·주의·확인 필요 화면을 모두 검증한다. 저장된 건강 상세에서도
  수의사 상담 진입점을 유지한다.
- 분석에 사용한 원본과 파생 썸네일은 분석 완료 후 모두 삭제한다. AI 기록에는
  사진이 아닌 날짜·반려동물·결과 라벨·메모만 보존한다. 향후 사진 보존은
  별도 명시적 opt-in과 개인정보처리방침 개정 없이는 도입하지 않는다.

### 피드

- 피드 사진을 가장 큰 시각 요소로 두고 프로필·행동·본문을 단순한 한 흐름으로
  읽게 한다.
- 좋아요·댓글·공유·저장은 44pt 영역과 의미 라벨을 유지한다.
- 피드는 팔로우 기반 사진·영상 일상 스트림으로 고정한다.
- 이번 Wave의 피드는 사진 1장 이상을 필수로 하고 동영상은 썸네일·트랜스코딩·
  용량·신고 계약이 준비될 때까지 후속 범위로 제외한다.
- 게시물·댓글·사용자 메뉴에서 신고와 차단으로 진입할 수 있어야 하며,
  차단한 사용자의 콘텐츠·알림·검색 결과를 즉시 제외한다.
- 스토리는 이번 개선 범위에 포함하지 않는다. 피드 작성·탐색·신뢰도 지표가
  안정된 뒤 별도 기획으로 검토한다.

### 커뮤니티

- 텍스트 중심 compact row를 사용하고 피드 카드 스타일을 재사용하지 않는다.
- 카테고리, 제목, 한 줄 미리보기, 작성자/시간, 댓글 수만 목록에 노출한다.
- 커뮤니티 글쓰기와 피드 글쓰기의 진입 아이콘·제목을 명확히 구분한다.
- 커뮤니티는 주제·게시판 기반 질문과 정보 교환으로 고정하며 팔로우 기반
  피드와 동일한 정렬·추천 문법을 사용하지 않는다.
- 카테고리는 `질문 / 정보 / 자랑 / 일상` 단일 taxonomy로 고정한다.
  사용자 간 진단을 유도할 수 있는 “건강 상담” 카테고리는 사용하지 않는다.
- 게시물·댓글·사용자 신고와 차단 진입점은 피드와 같은 위치 규칙을 사용한다.
- 커뮤니티 작성은 카테고리, 제목, 본문이 필수이며 사진·태그는 선택이다.
  피드 작성은 사진/영상과 본문 중심이며 커뮤니티 제목·카테고리를 노출하지
  않는다. 두 화면은 공용 draft 인프라를 사용하되 `feed`와 `community`로
  namespace를 분리하고 다른 유형으로 복구하지 않는다. 임시 저장 목록도
  작성 유형별로 진입한다.
- 게시물 상세과 댓글의 overflow에도 신고를 제공하고, 설정의 도움말 그룹에는
  운영 연락처·이용약관·커뮤니티 가이드라인 진입점을 둔다.
- 타 사용자 프로필에는 팔로우/언팔로우, 팔로워·팔로잉 목록과 페이지네이션을
  제공한다. 내 게시물·댓글은 수정/삭제, 타인 콘텐츠는 정확한 대상별
  신고/차단 메뉴를 사용한다. 신고는 사유 선택→접수 결과, 차단은 확인 단계를
  거친다.

### MY

- 프로필 이미지 높이를 이름부터 통계 하단까지 맞춘다.
- 이름과 게시글 통계 시작선을 맞추고 통계 사이 구분선은 사용하지 않는다.
- 소개는 이미지 아래가 아니라 프로필 surface 하단의 한 줄 행동으로 둔다.
- 대표 반려동물은 네이비 배경에서 튀지 않는 `#F8FBFE` surface를 사용한다.
- 내 게시글/저장 탭 이하는 중립 캔버스로 전환한다.

### 인증·온보딩

- 로그인은 웜 뉴트럴 단일 배경으로 통일한다.
- 이메일·비밀번호·로그인 → 보조 링크 → 소셜 로그인의 순서를 유지한다.
- 이메일 형식과 비밀번호 규칙은 입력 후 인라인으로 검증하고, 비활성 CTA 이유를
  사용자가 이해할 수 있게 한다.
- 회원가입·비밀번호 찾기에도 동일 scaffold와 하단 CTA 구조를 적용한다.
- 회원가입에는 이용약관·개인정보 수집 동의·연령 확인을 개별 항목으로
  제공하고, 설정에는 개인정보처리방침과 앱 정보·버전·오픈소스 라이선스
  진입점을 명시한다.
- 소셜 로그인은 제공사 공식 에셋과 문구를 사용한다. Apple은
  “Apple로 로그인”, Google은 “Google로 로그인”, Kakao는 “카카오 로그인”으로
  고정하고 OAuth 구현 계약은 변경하지 않는다.
- 세션 만료 시 한 번의 조용한 갱신을 시도한 뒤 실패하면 현재 입력·탐색
  context를 보존하고 로그인으로 안내한다.

### 플레이스·위치 선택

- 명시적 뒤로가기를 추가한다.
- 지도 인증 실패 시 REST 결과 목록과 검색·상세·저장은 계속 사용할 수 있게 한다.
- “다시 시도”는 새 플랫폼 뷰를 만들며, 동일 실패 Future를 재사용하지 않는다.
- 재시도는 최대 2회이며 이후 해당 세션은 리스트 전용 모드로 고정한다.
- 목업과 구현 테스트는 지도 성공, 실패 후 재시도, 리스트 전용의 세 상태를
  모두 포함한다.
- 카테고리 탭은 업종 의미 필터를 통과한 결과만 보여준다.
- 지도 성공 후 draggable sheet, padding, marker, 카메라 이동을 실기기에서
  검증한다.
- 기본은 지도 우선이며 실패 시 리스트 전용으로 강등한다. 성공 목업은
  marker·draggable sheet·full-map을, 위치 선택 목업은 검색·핀 이동·확정을
  각각 보여준다. sheet resize에서는 지도의 child view 크기 갱신과
  `keepLevelOnResize` 적용 여부를 실기기에서 검증한다.
- Kakao Local 실응답에 없는 별점·리뷰 수는 표시하지 않는다. 목록에는
  거리·카테고리·주소·영업 정보가 실제 응답이나 검증된 별도 출처에 있을 때만
  표시한다. 동물병원은 카테고리 코드, 펫카페·미용은 키워드+업종 의미 필터라는
  질의 전략을 단일 helper로 유지한다.
- 전체지도 가로 pan과 iOS edge-swipe-back, sheet drag와 목록 scroll의
  gesture 우선순위를 명시한다. 작성 modal은 뒤로가기 대신 닫기·취소를 쓴다.
- Kakao 지도 로고는 가리거나 제거하지 않는다.

### 설정·보조 화면

- 설정은 현재의 그룹형 list surface를 표준으로 채택한다.
- 법적·도움말·앱 정보는 동일 app bar와 텍스트 폭을 사용한다.
- 삭제·로그아웃은 일반 메뉴와 시각적으로 분리하고 확인 단계를 둔다.

### 작성·공용 상태

- 피드·커뮤니티 작성은 고정 CTA와 Safe Area를 함께 검증하고, 이탈 시
  저장 안 함/임시 저장/계속 작성 세 선택을 제공한다.
- 게시물 위치는 기본 미첨부다. 사용자가 직접 켠 경우에만 첨부하며 공개
  정확도 상한은 시·군·구로 제한한다. 지도 실패 때도 REST 검색 목록으로
  위치를 고를 수 있고 정확 좌표는 게시물에 공개하지 않는다.
- 오류는 네트워크, 권한, 인증 만료, 서버, 결과 없음으로 분류하고 각 상태에
  재시도, 설정 이동, 로그인, 문의, 필터 초기화 중 하나의 복구 행동을 둔다.
- 네트워크 오류와 세션 만료는 같은 화면이나 CTA로 합치지 않는다. 권한은
  설정 이동, 서버 오류는 재시도+문의 코드, 인증 만료는 context 보존 후
  로그인만 노출한다.
- 문의용 오류 코드는 키·URI·payload·SDK 원문을 포함하지 않는 짧은
  비밀 비포함 코드만 사용한다.
- 대표 반려동물 변경은 홈 요약·건강·AI·AI 기록 필터를 함께 무효화한다.
  현재 보고 있는 펫 삭제와 펫 0마리 전환도 별도 상태로 처리한다.
- 대표펫 변경은 영향 범위를 알리는 확인을 거친다. 대표펫 삭제 시 다른 펫이
  있으면 먼저 새 대표펫을 선택하고, 마지막 펫이면 펫 0마리 상태로 전환한다.
- 펫 삭제는 즉시 연관 건강·AI 기록을 물리 삭제하지 않는다. 계정 보존·삭제
  정책과 별도로 30일 복구 가능한 비활성화 후 영구 삭제 여부를 확정하며,
  구현 전 DB FK·Storage·개인정보 파기 계약을 별도 manifest로 검토한다.

## 5. 기능·백엔드 관점의 보존 조건

- K1/H2와 모든 신규 RPC의 `auth.uid()` 기준을 유지한다.
- 광범위 `public.users SELECT`와 caller-id 인자 RPC를 다시 도입하지 않는다.
- Apple OAuth, URL scheme, entitlement, `shareOrigin`을 변경하지 않는다.
- AI 오류에서 DB·SDK 원문, URI, 키, 응답 payload를 사용자나 로그에 노출하지 않는다.
- 장소 저장 schemaVersion과 손상 데이터 read-only fallback을 유지한다.
- 피드·팔로우·차단·알림은 낙관적 UI와 서버 확정 상태를 구분한다.
- 신고는 게시물·댓글·사용자 단위의 서버 상태를 구분하고, 중복 신고와
  처리 중 상태를 안전하게 표시한다.
- UGC는 부적절 콘텐츠 필터, 신고, 차단, 연락처 제공이라는 App Store
  Guideline 1.2 요구를 구현·검증 범위에 포함한다.
- 공개 위치는 옵트인·시군구 단위이며 원좌표·정확 주소는 게시물 payload와
  로그에 저장하지 않는다.
- offset pagination은 데이터 변동 시 중복·누락을 만들 수 있으므로 신규 화면부터
  stable cursor/keyset을 우선한다.

## 7. 승인 후 구현 순서

1. Wave 0: 공용 scaffold, 접근성 토큰, app bar, 상태 화면, 하단 CTA,
   건강 일정 selector, pet scope 무효화 규칙
2. Wave 1: 인증·비밀번호 찾기·설정·반려동물 관리, 홈 shell과 AI 진입 CTA
3. Wave 2: MY·피드·커뮤니티·작성·신고·차단 필터링
4. Wave 3: 건강·플레이스·위치 선택·지도 리스트 전용 모드
5. Wave 4: 홈 요약 카드·AI 분석·AI 기록

각 Wave는 별도 manifest와 acceptance criteria를 작성한 뒤 구현한다. 매 Wave마다
format → analyze → 관련 테스트 → 전체 테스트 → iOS 시뮬레이터 직접 조작 →
Claude/Codex diff 리뷰를 통과해야 다음 Wave로 이동한다.

후속 사용자 지시를 우선해 실제 실행 범위는 다음처럼 조정했다.

1. Wave 0: opt-in UI foundation과 동결 범위 verifier
2. Wave 1: 인증·비밀번호 재설정·설정·반려동물 관리
3. Wave 2: MY·피드·커뮤니티·작성·신고·차단
4. Wave 3: 건강
5. Wave 4: 소셜 위치 선택과 AI 기록 목록

홈과 AI 감정·건강 분석 결과 상세는 후속 사용자 지시에 따라 전 Wave에서
수정하지 않았다. 플레이스의 Home 병원 지도도 신규 UI 범위에서 제외했고,
병합 직후 존재한 iOS Kakao 안정화 diff만 보존했다.

## 8. Claude 3차 리뷰 결론과 Codex 권고

Claude의 목업 8장 3차 검토 결과는 `CHANGES_REQUIRED`였다. 사용자 방향 승인
전에 확정해야 하는 두 계약에 대해 Codex는 다음처럼 권고한다.

1. AI 사진 보존: 원본·파생 썸네일 모두 분석 완료 후 삭제하고 기록에는
   구조화된 결과와 메모만 보존한다.
2. 보호자 기록: 이번 AI 개선 범위에는 신규 입력·테이블을 추가하지 않는다.
   식욕·활동량·구토는 기존 건강 기록에서 관리하고 AI 연동은 별도
   `auth.uid()` RLS 설계 후 검토한다.

함께 고정할 정리안:

- 피드 사진 필수, 동영상 후속
- 커뮤니티 `질문/정보/자랑/일상` 단일 taxonomy
- 피드·커뮤니티 draft namespace 분리
- 지도 실패/리스트 전용과 펫 0마리 상태는 구현 manifest의 P0 acceptance
  화면으로 복원
- 팔로우·내 콘텐츠 수정/삭제·신고 사유·차단 확인을 소셜 acceptance에 포함
- 가입 동의·처리방침·앱 정보·오픈소스 고지를 인증/설정 acceptance에 포함
- Kakao Local 응답에 없는 별점·리뷰 수를 표시하지 않음
- AI 정상/주의/확인 필요 세 결과와 저장 상세 상담 진입점을 검증
