> 상태: 2026-07-19 사용자 재개 지시에 따른 Codex 구현 승인. Claude 한도 시

## 1. 목표

Feed에서 게시물을 발견한 뒤 상세를 열고, 좋아요·댓글·답글·저장·공유·신고·차단을 수행하는 흐름을 하나의 신뢰 가능한 경험으로 마감한다.

1. 피드 카드와 게시물 상세의 좋아요·댓글·저장 상태가 서로 어긋나지 않는다.
2. 좋아요 수를 누르면 검색 가능한 사용자 목록이 열린다.
3. 댓글과 답글의 작성·좋아요·삭제·신고가 명확하고 실패 시 안전하게 복구된다.
4. 게시물 상세에서도 작성자 프로필, 공유, 저장, 신고·차단 또는 수정·삭제가 모두 접근 가능하다.
5. 기존 감정 분석 게시물의 의미와 법무 경계를 보존한다. confidence 수치와 진단 표현은 노출하지 않는다.

### 2.3 이미 양호하여 보존할 부분

- 댓글/답글 생성 실패 시 입력 내용을 보존한다.
- 댓글 총개수는 서버 정본을 사용하며 로드 더보기와 별도로 관리한다.
- 댓글·답글 좋아요와 삭제는 항목별 pending lock을 가진다.
- 답글은 처음 두 개만 보여주고 나머지를 펼칠 수 있다.
- 좋아요 사용자 목록은 300ms 검색, cursor 페이지네이션, stale response 차단, 행 단위 팔로우 rollback을 가진다.
- 좋아요·댓글·전송 주요 동작은 최소 44dp 탭 영역을 가진다.
- 더블탭은 이미 좋아요인 게시물을 취소하지 않는다.
- 감정 게시물은 감정 라벨만 노출하고 confidence 백분율을 노출하지 않는다.

## 3. 확정 제안 UX

### 3.1 게시물 상세

- 상단: 뒤로가기 / `게시글` / 더보기.
- 작성자 행: 아바타·이름·상대시간 전체를 눌러 프로필 이동.
- 본문: 미디어 → 캡션 → 감정 컨텍스트 카드 순서를 유지한다.
- 액션 행:
  - 하트와 좋아요 수는 분리된 44dp 탭 대상이다.
  - 댓글 아이콘·개수는 입력창으로 이동한다.
  - 공유 버튼을 추가한다.
  - 저장 버튼과 저장 위치 변경은 기존 계약을 보존한다.
- 댓글 섹션: `댓글 n` 헤더, 댓글 목록, 하단 고정 composer.
- 작성자 게시물 옵션: 수정, 삭제.
- 타인 게시물 옵션: 신고, 사용자 차단.

### 3.2 댓글·답글

- 댓글 행: 아바타, 이름, 작성 시각, 본문, 좋아요, `답글 달기`, 더보기.
- 게시물 작성자의 댓글에는 `작성자` 텍스트 배지를 표시한다.
- 소유자 더보기: 삭제.
- 타인 더보기: 신고.
- 답글도 동일한 좋아요·신고 계약을 갖되 한 단계 들여쓰기만 허용한다.
- 답글에서 `답글 달기`를 선택하면 같은 최상위 스레드 아래에 추가하고 composer에는 `OOO에게 답글`을 표시한다.
- 신고 성공은 Repository 성공 이후에만 표시하며, 실패 원문·DB 정보는 노출하지 않는다.

### 3.3 좋아요 사용자 목록

- 상단: 드래그 핸들, 명시적 닫기, `좋아요 n`.
- 이름·사용자 이름 검색.
- 프로필 행: 아바타, 표시 이름, `@username`, 팔로우/팔로잉 또는 `나`.
- 검색·다음 페이지 실패를 구분하고 각각 재시도한다.
- 화면 밖에서 바뀐 팔로우 상태는 새 목록 요청에서 서버 정본으로 갱신한다.

### 3.4 상태 피드백

- optimistic update는 좋아요·팔로우에만 사용하고 실패 시 해당 항목만 rollback한다.
- 신고·삭제·차단은 서버 성공 전 성공 메시지를 표시하지 않는다.
- raw exception, SQL, 키, 토큰, 내부 사용자 ID를 사용자 문구에 노출하지 않는다.
- 삭제·차단 등 부정 상태는 기존 `AppTheme` 의미 토큰만 사용하고 신규 빨강을 추가하지 않는다.

## 4. 구현 전략

### F2A — 정확성·안전

1. 게시물 신고를 실제 `SocialRepository.reportPost`에 연결한다.
2. `SocialRepository.reportComment` 계약과 구현을 추가한다. 기존 DataSource/DB 계약을 재사용하며 DB 변경은 하지 않는다.
3. 게시물/댓글 공용 신고 사유 시트를 만든다.
4. 상세의 직접 Supabase 의존을 제거한다.
5. 카드에서 상세를 연 뒤 복귀할 때 게시물·좋아요·저장 정본을 재조회하여 surface state를 갱신한다.
6. 상세에도 작성자/타인 옵션과 공유를 연결한다.

### F2B — UI/UX 마감

1. `CommentComposer`를 공용화한다.
2. 답글 선택 시 입력창 자동 포커스와 키보드 안전 영역을 보장한다.
3. 댓글·답글 메뉴와 `작성자` 배지를 정리한다.
4. 좋아요 목록 헤더·닫기·검색 상태를 개선한다.
5. 상세 본문을 화면 전용 widget으로 분리해 한 파일의 책임을 줄인다.
