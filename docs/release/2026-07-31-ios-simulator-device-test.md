비밀번호 재설정 요청은 테스트용 비회원 이메일로 수행했다. 화면 전환과
오류 노출 방지 계약만 확인했으며 실제 메일 수신·딥링크 완료는 검증하지
않았다.

## UI 점검과 즉시 수정

- iPhone 로그인·회원가입 화면은 작은 화면에서 overflow 없이 유지됐다.
- iPad에서는 콘텐츠 폭이 480pt 이하로 제한되어 세로·가로 모두 과도하게
  늘어나지 않았다.
- 비밀번호 인증 코드 화면에서 앱바 제목과 본문 제목이 중복되던 문제를
  발견해 본문 제목을 제거했다.
- 수정 후 iPhone 최신 빌드에서 제목이 한 번만 노출되고, 설명→OTP→버튼→
  재발송→안내 순서의 위계가 유지되는 것을 다시 확인했다.
- 해당 회귀 테스트에 제목 단일 노출 검증을 추가했다.

## 현재 Simulator만으로 완료할 수 없는 항목

- 실제 Apple·Google·Kakao 계정 OAuth 완료
- 실제 받은 이메일 인증 코드와 비밀번호 변경 완료
- 로그인 후 게시글·커뮤니티 글·팔로우·좋아요·채팅·신고·차단 전체 흐름
- Apple 계정 재인증과 credential revoke 기반 회원탈퇴
- APNs foreground·background·terminated push
- 서명 릴리스 빌드의 Kakao 지도와 권한 복구

위 항목에는 QA 계정, 실제 OAuth 계정, 이메일 수신함, 운영 Edge 설정,
Firebase APNs 설정 또는 실기기가 필요하다. 계정 정보는 문서·코드·로그에
기록하지 않고 사용자가 Simulator나 실기기에 직접 입력하는 방식으로
검증한다.

## 다음 실기기 실행 순서

1. 비운영 QA 계정 2개를 준비한다.
2. 사용자가 OAuth·이메일 계정 정보를 직접 입력한다.
3. 가입·로그인·로그아웃·비밀번호 변경을 검증한다.
4. 두 계정으로 게시글, 댓글, 팔로우, 좋아요, 저장, 채팅, 신고, 차단을
   상호 검증한다.
5. Apple 계정으로 회원탈퇴를 요청하고 세션 차단·30일 복구·revoke를
   운영 로그의 비식별 결과 코드로 확인한다.
6. APNs를 foreground, background, terminated 상태에서 각각 확인한다.
7. 서명 archive 설치본으로 Kakao 지도, 카메라, 사진, 마이크, 위치 권한을
   허용·거부·복구 순서로 확인한다.
